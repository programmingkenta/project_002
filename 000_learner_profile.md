# Learner Profile

## Interview

**Q1. What's your background with programming?**
**Answer:** Beginner programmer with no familiarity with Git, no experience using an IDE or GitHub. Planning to learn programming through Python.

*Commentary: Starting from absolute zero. This means I need to explain things that experienced programmers take for granted - what a file is in programming context, how to run code, what errors mean. No assumptions.*

**Q2. Where do you want programming to take you?**
**Answer:** Learning the principles of programming and having a basic foundation in Python. Wants to be a project manager with programming fundamentals. Has a learning project in mind: building a 3D pixel map of a city.

*Commentary: Not aiming to become a full-time developer - wants technical literacy to work effectively on tech projects as a PM. The 3D city project is ambitious and visual, which is motivating. It will naturally introduce coordinates, data structures, loops, and visualization. This goal shapes the curriculum: focus on fundamentals that help them understand what developers do, communicate technical concepts, and build their passion project.*

**Q3. Tell me about yourself.**
**Answer:** Currently a project manager without programming experience, but wants to work on tech projects.

*Commentary: PM background is an asset - they already understand breaking complex work into tasks, dependencies, workflows. I can use project management analogies: variables are like project resources, functions are like reusable task templates, debugging is like troubleshooting a blocked project.*

**Q4. How do you learn best?**
**Answer:** Prefers a balance of theory and practice with hands-on experience. Self-identifies as needing more time to grasp concepts compared to average - simple explanations help.

*Commentary: This is crucial. I must: (1) Keep tutorials focused on ONE concept at a time, (2) Use simple analogies and ELI5 explanations, (3) Always include hands-on exercises, (4) Build slowly and reinforce before moving on, (5) Never rush or assume understanding. Patience and clarity over speed.*

## Teaching Approach

- **Pacing:** Slow and steady. One concept per tutorial, fully understood before moving on.
- **Style:** Simple language, PM-friendly analogies, lots of "why" before "how."
- **Practice:** Every tutorial ends with a hands-on exercise, ideally connected to the 3D city project when possible.
- **Reinforcement:** Regular quizzes to verify retention before building on concepts.
- **Goal alignment:** Frame learning around becoming a technically-literate PM who can build their city visualization project.
